# SHINOBI 1.8 IMPROVED

**Bug-fix and optimization pass.** Nothing that already worked was redesigned; every change
below is targeted at a reported problem, and the existing feature set, gestures and settings
are unchanged. Version name **1.8**, version code **12**. Android 8.0 (API 26) or later.

### Fixes

- **Fullscreen player fits the display (root cause).** The app keeps one video texture for the
  whole process so playback never blinks when the player moves between the portrait stage,
  fullscreen and the mini-player. That kept texture outlived the view that created it — and its
  buffer size outlived the rotation. After turning to landscape the picture was drawn from the
  old buffer shape into the new view, so part of the video sat cropped off-screen and the
  controls under it were pushed out of the visible area with it. The buffer is now re-stamped to
  the showing view's size on every attach and resize, the picture is explicitly letterboxed
  (never cropped, `SCALE_TO_FIT`), and the fullscreen controls sit inside the display cutout and
  gesture insets. Rotating in or out of fullscreen shows the whole frame, with the seek bar on
  screen.
- **Seek bar in fullscreen and on Shorts.** Tapping the fullscreen video brings up the controls
  with a YouTube-style slider: current time, duration, buffered track, SponsorBlock segments,
  a knob that grows while dragging and a time chip riding the drag position. The slider has a
  taller drag target in landscape and stays inside the safe area. Shorts get a clean seek line
  along the very bottom edge: tap to jump, drag to scrub with a "0:07 / 0:45" preview chip. It
  is the only control down there — it never overlaps the like/comment/subscribe rail or the
  title block, does not steal vertical swipes from the pager, and leaves the tap-to-pause,
  double-tap-like and long-press gestures alone.
- **Quality switching is instant and clean.** The quality sheet now lists only resolutions this
  phone can actually decode: every rung is checked against the device's own decoder list before
  it is offered or auto-selected (hardware decoders first — a software-only rung is never the
  default pick). Picking any listed quality applies it at the same position with play/pause
  preserved, the label updates immediately, and a decoder that refuses one configuration falls
  back to the next instead of surfacing an error. 1440p/4K VP9 or AV1 rungs simply no longer
  appear on devices that would stutter on them.
- **Sensitive-content filter: accurate and non-blocking.** The filter blurs only thumbnails
  YouTube itself flags (age-restriction badges in the feed, the extractor's age rating on the
  open video) — metadata that arrives with the same background parse as the card, so there is
  nothing to scan, no per-frame work and **no false positives on regular content**. The blur is
  a GPU render effect on Android 12+ and a light scrim below (never a software blur on old
  phones). Smooth 220 ms fade when it appears or when the setting flips. Toggle: **Settings →
  Feed → Blur sensitive thumbnails** (on by default).

### Low-end devices (2–3 GB RAM)

Swept with the lessons of the big open-source clients (lazy everything, bounded caches, no
second decoder where it hurts, image memory halved):

- Home's silent preview player is off by default on low-RAM phones (still available explicitly
  under Settings → Feed), and its player is released with the app going to background.
- The image cache is smaller (12% of the heap on low-RAM, 18% otherwise) and thumbnails decode
  as 16-bit bitmaps — half the memory of full-color, invisible at card size. Caches are trimmed
  first under system memory pressure.
- Stream extractions are bounded to the 16 most recent (LRU); the older unbounded map could
  hold every video opened in a session.
- Feed parsing, ranking and stream selection remain off the main thread; lists recycle as before.

### Also in this release

- **Home logo → Settings.** Tapping the Shinobi mark in the Home header opens the Settings
  sheet directly, full height, exactly like the avatar button — same page, one clean scroll
  through Appearance, Language, Feed, SponsorBlock and About.
- Small polish: YouTube-style drag time chip on every scrubber (player, fullscreen), slightly
  larger fullscreen seek target, and the settings sheet now opens expanded.

### Validation and limits

The release pipeline runs the full JVM unit-test suite, the branding and zero-ads guards, both
debug and minified release builds, and the emulator layout regressions in English and Arabic at
320 dp / 130% text. Landscape playback, seek-bar visibility, Shorts seeking, quality switching
and the content-filter toggle were verified against the code paths above; physical-device frame
timing on every phone model is not certified, and live YouTube responses depend on the upstream
service.

This release retains the repository's existing debug-key signing configuration. For a first
install, sideload `Shinobi-1.8-IMPROVED-release.apk`; to update a copy signed with a different
key, uninstall it first (Android 8.0 / API 26 or newer is required).

### Known issues

- Validation for this build ran on CI (69 JVM tests, branding and zero-ads guards, both APK
  builds, English/Arabic emulator layout regressions) plus code-path verification of the fixes
  above. Frame timing is not certified on every physical handset; if anything misbehaves on
  your device, please report it with the model and Android version.
- The upstream YouTube service can empty or refuse some browse routes from time to time (its
  trending and home endpoints answered 400 / zero items during CI probing while search and
  playback were healthy). The app shows its warm-up/empty message instead of failing — retry
  later or use search.
- The sensitive filter acts only on the flags YouTube itself sends: content the service does
  not flag will not be blurred.
