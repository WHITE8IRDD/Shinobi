# SHINOBI 2.0

**Status: release candidate — not published.** Package version 2.0 (code 14).
The build artifact includes `SHINOBI 2.0.apk`. This is not a claim that the
mandatory real-network/physical-device acceptance checks have been completed.

## Changes

- Fullscreen storyboard previews now check `Size.isSpecified` before accessing dimensions.
  Loading/failed images keep the poster/time fallback. Preview decoding is bounded to
  2048px; invalid/overflowing sprite geometry is rejected. The preview no longer moves
  the seek target when inserted. Pointer callbacks use current handlers; targets are clamped.
- Seek commands are only sent to the connected controller for the currently displayed,
  seekable media item with a valid duration. Paused seeking does not start playback.
- Shorts: persistent right-side Like, Dislike, Comments, Share, More; creator/title beside
  the rail; red accessible seek strip; independent mute; flat navigation outside the video.
  No main-app floating pill, bottom vignette, gesture guard or sideways tab swipe overlays
  the Shorts viewport. The obsolete auto-hide preference has been removed.
- Main-thread work: DASH manifest generation/XML parsing now runs on the service resolver
  before the media item is handed to ExoPlayer. Hardware codec capability checks are cached.
  Collapsing headers update synchronously while scrolling, rather than launching a coroutine
  and taking an animation mutex per pointer event. Mini-player progress redraws just its leaf;
  SponsorBlock Ask polling no longer recomposes the full video-control tree.
- Memory/workload: at most two pending speculative extractions, deduplicated before enqueue;
  no caller-runs fallback. Bounded media buffers (24 MiB on low-RAM devices / 48 MiB otherwise),
  release of Home's extra decoder when real playback owns the screen, no extra Shorts
  beyond-viewport page, and explicit service worker/timer cleanup on destruction.

## Morocco Trending: important upstream limitation

The previous implementation explicitly defaulted Morocco to **Gaming**, because Morocco
is outside YouTube Charts' Music/Movie launch list. That is not a combined regional chart.

The combined `FEtrending` feed was retired by YouTube. Our 2026-10-15 anonymous CI probes
returned HTTP 400 for both WEB and MWEB, including NewPipeExtractor's exact Videos-tab
parameter. The old HTML page no longer exposes the old Trending feed. See
[`../probes/trending-MA.md`](../probes/trending-MA.md).

**All** now requests that original endpoint with the selected country, without account
cookies and without reranking. When unavailable it says so. Category charts are explicit
choices; Gaming, search results, podcasts and another country's charts are never passed
off as the combined Moroccan ranking. Category extraction uses request-local country state.

Consequently, the request to mirror a combined Moroccan news/current-events/music/viral
Trending list **cannot currently be fulfilled from that retired public feed**. This candidate
does not fabricate one. Publishing requires an explicit decision about that limitation.

## Verification and release gate

See [`../testing/2.0-acceptance.md`](../testing/2.0-acceptance.md) for test coverage,
measured diagnostics, limitations and remaining manual checks. Automated offline tests
are not proof of live YouTube seeking on several devices, nor of smoothness on 2–3 GB phones.
Do not tag/publish this candidate as fully verified until those checks are signed off.

The existing release signing configuration uses a debug signing key. An APK signed by a
different CI-generated key may require uninstalling the existing app (losing local data).
A stable private release signing identity remains a separate distribution requirement.
