# SHINOBI 1.9 IMPROVED

Version **1.9**, version code **13**. Android 8.0 (API 26) or newer.

## Targeted fixes

- **Fullscreen fit and missing landscape seek bar:** locale wrapping now overrides only
  language/layout direction, not the launch-time device configuration. Rotation can therefore
  update Compose's orientation and screen dimensions instead of stretching a portrait stage
  beyond the landscape window. The fullscreen video uses centered aspect-fit with the whole
  frame visible; controls and the scrubber remain inside cutout/gesture-safe bounds.
- **Fullscreen seeking:** current time, duration, buffered progress, tap-to-seek and horizontal
  drag-to-scrub remain available. Dragging now shows the corresponding storyboard thumbnail
  and timestamp, keeps the controls open even when holding the finger still, and cleans up on
  cancellation. Missing upstream storyboards fall back to the video thumbnail plus timestamp;
  this fallback is not a decoded seek frame. Sprite sheets are cached through Coil and cropped
  during drawing rather than allocating a bitmap for every finger movement. The seek track
  also supports accessibility progress actions.
- **Shorts swipe separation/performance:** each page clips its cover-scaled video, and the
  single shared texture stays on the settled page throughout a swipe. The next page masks
  retained frames until its own video renders. Playback work observes settled pages rather
  than mid-drag page changes; the next two stream extractions are prefetched, unrelated
  long-video prefetches do not compete during Shorts, and one media item/decoder is recycled
  instead of accumulating the normal queue behind Shorts. Cancelled detail loads cannot write
  a stale error into the next Short.
- **Mini-player versus Shorts:** both the mini-player and its collapsing morph are excluded
  while Shorts owns the screen (including loading and tab animations). The normal video's
  queue, position and playing/paused intent are suspended, then restored on leaving Shorts.
  Outgoing animated Shorts content cannot stop the restored video. Opening a normal video
  explicitly still opens its player; leaving Shorts without a suspended normal video creates
  no mini-player.

## Verification

The Android workflow runs the full JVM suite, debug and minified release builds, existing
English/Arabic narrow-screen/large-text layout tests, branding and zero-ads checks, plus new
player regressions:

- real landscape → portrait rotation of a locale-wrapped activity;
- fullscreen seek-bar bounds and centered tall/wide aspect-fit geometry;
- an offline H.264 video decoded through ExoPlayer, MediaSession, MediaController and the real
  TextureView, checking that all four colored picture borders are visible in landscape;
- scrubber tap, drag preview, release and accessibility seeking;
- one Shorts texture across page swipes, with retained-frame masking;
- suspended mini-player queue/position restoration, playing/paused intent, idempotent entry/exit,
  and Shorts-only exit with no mini-player;
- storyboard grid/sheet mapping, end-of-video clamping and invalid/missing metadata.

These are automated emulator and unit checks, not a claim of physical-handset testing or
measured frame-time guarantees. Live Shorts loading depends on YouTube and network conditions;
physical-device swipe smoothness, OEM system-bar behavior and live storyboard availability
still warrant a handset smoke test.

## Installation/signing

Install **SHINOBI 1.9 IMPROVED.apk** from this release. This retains the repository's existing
Gradle debug-signing setup for release builds; CI-generated signing keys are not guaranteed to
match an APK from an earlier run. Android may require uninstalling a differently signed copy
first; export any local data you want to keep before uninstalling. The debug APK is supplied
separately for diagnosis.
