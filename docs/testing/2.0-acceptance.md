# SHINOBI 2.0 acceptance and evidence

## Root cause and regression coverage

The 1.9 fullscreen drag path inserts `SeekThumbnail`. Coil's painter reports
`Size.Unspecified` while empty/loading/failed; calling `.width` or `.height` on that
sentinel throws `IllegalStateException`. The original draw code accessed those properties
without checking `isSpecified`. The previous drag test passed a **null storyboard**, so
it exercised only the poster fallback and could not detect this fault.

`ReleaseRegressionTest` now decodes generated local 4-second, 180-second landscape and
45-second vertical videos through real ExoPlayer → MediaSession → MediaController. It:

- performs 36 taps and 36 drags across early/middle/end targets on three timelines;
- keeps playback paused, checks the controller's target position and absence of player errors;
- draws a real Coil storyboard painter with a delayed offline interceptor, exercising
  unspecified/loading and success states; also tests missing/error sheets and null metadata;
- checks that inserting a preview leaves the seek target's bounds unchanged;
- tests accessibility seeking;
- checks Shorts metadata/rail/seek/navigation separation at 320dp in LTR and RTL and seeks
  the real vertical-video timeline.

Existing rotation/surface-retention/Shorts ownership regressions remain enabled. Unit tests
cover sprite sheet mapping and invalid/overflowing geometry, finite/clamped pointer targets,
and country/category cache isolation/cancellation. A retired general chart must produce an
unavailable state without making a Gaming or search request.

## Performance diagnostics (not a certification)

`PerformanceSmokeTest` records `Window.FrameMetrics.TOTAL_DURATION` while scrolling 120
offline real `VideoCard` components through the collapsing header. It reports sample count,
median, p95, frames over 16.7/33.3ms, total process PSS and Java heap use. Reports are in the
CI `screenshots` artifact (`performance-scroll.txt`) and Checks annotations.

This uses a debug build and emulator; it excludes real network/image/download load and is
not a whole-app profile, a before/after benchmark, or a low-end hardware certification.
The measurements intentionally have no arbitrary "smooth" pass threshold. Reproduce on
physical hardware with animations enabled and a minified/profileable release build; use
Perfetto/System Trace for main-thread, decoder, GC and frame-deadline correlation.

## Required manual release checks — still pending

- [ ] Real YouTube playback on several videos, cold and warm sprite sheets; repeated
      fullscreen taps/drags at early/middle/end, paused and playing, including rotation.
- [ ] Slow/offline network, missing storyboards, live/unseekable media, expired stream recovery,
      rapid video changes and controller reconnection; no crash or unintended playback.
- [ ] Shorts: paging, seeking vs vertical gestures, mute, all five actions, comments/share
      sheets, creator/channel navigation and return to the suspended normal video.
- [ ] Morocco over a real device network: category results scoped to MA; no gaming substituted
      for All; agree on the unavailable combined Trending feed rather than fabricate a list.
- [ ] 2 GB and 3 GB physical phones: feeds, search typing/pagination, trending, Shorts, player,
      background/PiP and sustained use. Record release-build frame percentiles, memory and traces.
- [ ] Verify upgrade signing and installation; only then publish `SHINOBI 2.0.apk`.

## Upstream implementation study

These are source-level implementation references, not claims that another project's code
was copied wholesale or that its different UI/player stack guarantees Shinobi's behaviour.

- NewPipe: `player/ui/VideoPlayerUi.java`, `onStartTrackingTouch` / `onStopTrackingTouch`:
  keep preview separate from seek commit, commit on release and maintain control visibility.
  https://github.com/TeamNewPipe/NewPipe/blob/dev/app/src/main/java/org/schabi/newpipe/player/ui/VideoPlayerUi.java
- Tubular: same seek lifecycle in its maintained NewPipe-derived UI:
  https://github.com/polymorphicshade/Tubular/blob/dev/app/src/main/java/org/schabi/newpipe/player/ui/VideoPlayerUi.java
- PipePipe: null-safe preview handling and bounded preview resize:
  https://github.com/InfinityLoop1308/PipePipeClient/blob/dev/app/src/main/java/org/schabi/newpipe/player/seekbarpreview/SeekbarPreviewThumbnailHelper.java
- LibreTube: background/cancellable preview processing and bounded preview position:
  https://github.com/libre-tube/LibreTube/blob/master/app/src/main/java/com/github/libretube/ui/listeners/SeekbarPreviewListener.kt
- NewPipeExtractor v0.26.5, the exact dependency in this app: original `FEtrending` Videos
  parameter, regional kiosk extraction, separate category endpoints and chart coverage:
  https://github.com/TeamNewPipe/NewPipeExtractor/tree/v0.26.5/extractor/src/main/java/org/schabi/newpipe/extractor/services/youtube/extractors/kiosk

Applied principles: one owning player/surface, preview-only finger movement and one seek on
commit, safe absent/loading thumbnails, bounded image/work queues, background extraction
and honest separation of region and category. Shinobi uses Compose/Media3 rather than the
older View/ExoPlayer stacks, so its loading-state crash needed a Compose-specific fix.
